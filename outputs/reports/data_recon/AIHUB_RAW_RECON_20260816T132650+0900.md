## D. Schema

### JSON corpora

Record grain은 top-level `data[]` object 하나당 번역쌍 하나다. 공통 core는 `sn`, `data_set`, `domain`, `subdomain`, `ko`, `en`, `mt`, `source_language`, `target_language`, `word_count_ko`, `word_count_en`, `word_ratio`, `file_name`, `source`, `license`, `style`, `included_unknown_words`, `ner`이다. 영→한 파일은 `en_original`, 한→영 파일은 `ko_original`을 추가로 가진다.

## E. Pairability

- JSON: `ko`와 `en`이 같은 object에 공존하므로 direct pairable. `sn`은 file 내부 nonempty unique candidate이며 duplicate key 0건이다.
- XLSX: `원문`과 `번역문`이 같은 row에 공존하므로 direct pairable. `SID`/`ID`는 각 workbook 내부 duplicate 0건이다.
- 대화체: 단일 ID가 없다. `Set Nr.` + `발화자`도 100,000행 중 duplicate composite row 8건이므로 unique key가 아니다. `workbook_relative_path + sheet_name + physical_row_number`가 결정론적 fallback이다.
- Legacy 전체에서 `ID`/`SID` 값은 127,824개 후속 중복 후보가 있어 workbook namespace 없이 전역 key로 쓰면 안 된다.
- Raw pair hash 중복은 BLAKE2b-64 후보 집계이며 collision 가능성이 있으므로 확정 duplicate 판정이 아니다.

## H. Translation Provenance

- JSON은 direction별 `ko_original` 또는 `en_original`, machine translation candidate `mt`, final pair `ko`/`en`, source/target language, raw word counts, source, license, style을 함께 가진다.
- D025 direction은 영→한/한→영 모두 있으며 D026은 한→영이다. 관측된 `source_language`/`target_language` 값은 file direction과 일치한다.
- JSON `license`는 모든 고유-content record에서 raw metadata 값 `open`이었다. 이것은 파일 내부 주장일 뿐 라이선스 문서 검증이나 재배포 승인으로 승격하지 않는다.
- Legacy XLSX는 `원문`/`번역문`만으로 pair는 가능하지만 original-vs-MT-vs-final 단계, annotator, license, split provenance를 직접 설명하는 column이 없다. 따라서 translation provenance는 UNKNOWN이다.

## I. Risks

1. 원천/라벨링 JSON이 byte-identical이다. 폴더를 재귀 ingest하면 D025와 D026이 정확히 2배 집계되고, D025 ZIP까지 읽으면 validation을 추가 중복시킨다.
2. D025 raw pair duplicate와 train/validation overlap 후보가 크다. split 독립성 또는 QC 적합성을 이 reconnaissance로 승인할 수 없다.
3. Legacy ID는 file-scoped이고 대화체 composite도 8행 중복이다. 전역 key 오용 시 collision이 발생한다.
4. 일부 raw text에 zero-width, replacement character, HTML-like pattern, script mixing이 있다. 이번 audit은 위치/count만 기록하며 정규화 저장을 하지 않았다.
5. 뉴스 metadata는 빈 URL/자동분류가 많고 날짜 cell type도 workbook 간 datetime/integer로 다를 수 있다. ingest schema에서 type coercion 정책이 필요하다.
6. JSON `ner`는 대다수 null이나 일부 non-null이다. 구조/의미를 pair core와 분리해 다뤄야 한다.
7. 외부 AIHub 페이지·설명서·라이선스는 absolute local boundary 때문에 조사하지 않았다.

## J. Suitability

결론은 `CONDITIONAL_RAW_INGEST_FEASIBLE`이다. 이는 raw parser의 결정론적 실행 가능성에 대한 판단이며 G1 PASS 또는 QC acceptance가 아니다.

필수 조건:

1. 이 snapshot의 relative-path allowlist와 SHA-256을 고정한다.
2. physical folder가 아니라 SHA-256 고유 content를 기준으로 source/label copy와 ZIP member를 중복 제거한다.
3. JSON은 strict UTF-8 streaming `data[]`; XLSX는 workbook/sheet/physical-row 순서를 명시해 읽는다.
4. pair key는 JSON `sn`, workbook-scoped `SID`/`ID`, 대화체는 file+sheet+physical-row를 사용한다.
5. 다음 실행에서도 시작/종료 stat을 비교하고 변경 파일은 `DOWNLOAD_IN_PROGRESS`로 제외한다.
6. raw text와 metadata를 보존하고 normalization/QC 결정은 별도 승인 단계로 넘긴다.

## K. Unknowns

- 세 local directory의 정확한 AIHub dataset release ID, version, 배포일, 공식 split 생성 방법.
- Legacy XLSX의 translation workflow, machine/human translation 여부, annotator/reviewer 정보, license.
- JSON의 `mt`와 final `ko`/`en` 사이 편집 절차 및 `ner` non-null 구조의 공식 의미.
- D025 중복/validation overlap이 의도된 설계인지 오류인지.
- Raw metadata의 `open`이 현재 프로젝트의 사용·재배포 조건을 충족하는지.
- 외부 문서와의 completeness 대조. 이 audit은 local RAW_ROOT만 조사했으므로 판단하지 않았다.

## Method boundary

수행하지 않은 작업: o200k tokenization, Tokenization Premium 계산, morphology, normalization 저장, regression, inferential statistics, final QC acceptance, D-01 canonical registry 생성.
