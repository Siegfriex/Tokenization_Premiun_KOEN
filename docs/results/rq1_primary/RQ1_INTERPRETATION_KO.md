## 1. RQ1은 무엇을 검정했는가

의미적으로 대응되는 한국어–영어 문장쌍 각각에 대해, 고정된 tokenizer가 산출한 token 수의 비를
정의한다.

```
TP_i = T_KO,i / T_EN,i
Y_i  = log(TP_i)
```

검정 대상은 단 하나다.

```
H0 : Median(Y) = 0
H1 : Median(Y) > 0
```

즉 "한국어 쪽이 더 많은 token을 쓰는 경향이 중앙값 수준에서 존재하는가"를 묻는다. 이때 무엇을
묻지 **않았는지**가 똑같이 중요하다. 원인을 묻지 않았고, 다른 tokenizer를 묻지 않았으며, 평균을
묻지도 않았다.

## 2. 왜 logTP가 primary outcome인가

`TP`는 비(ratio)이므로 1을 중심으로 비대칭이다. 한국어가 두 배면 2, 절반이면 0.5인데, 두 경우는
"같은 크기의 반대 방향"임에도 1로부터의 거리가 1과 0.5로 다르다. 로그를 취하면 이 비대칭이
사라진다. `log(2) = 0.693`, `log(0.5) = -0.693`으로 대칭이 된다.

따라서 `logTP`에서 "0보다 크다"는 진술은 방향에 대해 편향되지 않은 진술이 되고, 부호가 곧
방향을 뜻하게 된다. 또한 `Median`은 단조변환에서 보존되므로 `Median(TP) = exp(Median(logTP))`가
정확히 성립한다 — 로그 척도에서 검정하고 비 척도로 되돌려 보고해도 값이 어긋나지 않는다.

## 3. median logTP = ln(4/3)의 의미

관측된 중앙값은 `0.28768207245178085`이고 이는 `ln(4/3)`과 double precision에서 정확히 같다.
비 척도로 되돌리면 `4/3 = 1.3333…`이다.

이것이 우연한 근사가 아니라는 점이 중요하다. `T_KO`와 `T_EN`이 정수이므로 `TP`는 유리수이고,
중앙값 근방의 질량이 몇 개의 단순한 정수비에 집중되어 있다. 중앙 pair를 기술하는 가장 정직한
방식은 소수점 이하 여러 자리의 실수가 아니라 **"4 대 3"이라는 비율 그 자체**다.

## 4. 왜 이를 "33.3% median pair premium"이라고 부를 수 있는가

`4/3 - 1 = 0.3333…`이므로 중앙 pair는 영어 대비 33.3% 더 많은 token을 쓴다. 다만 이 표현은
반드시 두 가지 수식어를 달아야 한다.

**median** — 중앙 pair에 대한 진술이지 모든 pair에 대한 진술이 아니다. 분포에는 33.3%보다 크거나
작은 pair가 양쪽으로 넓게 퍼져 있다.

**pair-level** — pair마다 비를 구한 뒤 그 중앙값을 취한 값이지, corpus 전체 token 수를 합해서
나눈 값이 아니다. 두 양은 일반적으로 일치하지 않는다.

```
Median(TP)  =  median_i ( T_KO,i / T_EN,i )
                ≠
aggregate   =  ( Σ_i T_KO,i ) / ( Σ_i T_EN,i )
```

API 비용처럼 총량이 문제인 맥락에서는 후자가 관련 있는 양이며, 이 연구는 후자를 primary로
보고하지 않았다. 따라서 "API 요금이 33% 오른다"는 진술은 이 결과가 지지하지 않는다.

## 5. 87.99% positive pair가 왜 중요한가

중앙값만으로는 분포의 모양을 알 수 없다. 소수의 극단값이 중앙값을 밀어 올린 상황과, 대다수
pair가 같은 방향을 가리키는 상황은 통계적으로 전혀 다른 이야기인데 중앙값 하나로는 구별되지
않는다.

```
TP > 1    3,375,095    87.9850%
TP = 1      196,718     5.1282%
TP < 1      264,175     6.8868%
```

약 88%가 같은 방향이라는 사실은 이 결과가 **분포 전반의 성질**임을 보여준다. 극단값 몇 개가
만들어낸 인공물이 아니다.

다만 이 수치는 기술통계이지 검정통계량이 아니다. `P(TP>1)`을 sign test의 p-value와 같은 것으로
읽어서는 안 된다.

## 6. Wilcoxon은 무엇을 말하는가

one-sample Wilcoxon signed-rank는 부호뿐 아니라 편차의 크기 순위까지 사용한다. 따라서 sign
test보다 검정력이 높지만, 그 대가로 분포의 대칭성 내지 위치이동(location-shift) 해석을
동반한다. 이 가정이 의심될 때를 대비해 SSOT §17.1이 sign test 병행을 규정하고 있다.

관측 결과 exact p는 double precision에서 underflow했고, 보고 형식은 `p < 1e-300`으로 제한한다.
`N ≈ 3.8M`에서 이 사실은 정보량이 크지 않다 — 어떤 미세한 편차도 유의해지기 때문이다.

## 7. tie-aware robustness가 왜 필요한가

first release가 보고한 sign test는 `logTP = 0`인 pair를 분모에서 제외했다. 표준적인 관례이지만,
그렇게 하면 검정이 다루는 모수가 바뀐다.

```
제외한 검정  :  P(Y > 0 | Y ≠ 0)      조건부 확률
median 주장  :  P(Y > 0)              주변 확률
```

이 cohort에서 tie는 196,718건, 전체의 5.13%다. 무시할 수 있는 규모가 아니므로 두 모수는 실질적
으로 갈라진다. 그래서 closeout에서 검정 이름을 `CONDITIONAL_NONZERO_SIGN_TEST`로 정정하고,
median 주장과 정확히 같은 대상을 검정하는 보수적 검정을 추가했다.

`Median(Y) = 0`이면 `P(Y>0) ≤ 1/2`이다. tie가 질량의 일부를 가져가므로 등호가 아니라 부등호가
되고, 검정은 least-favourable null인 `Binomial(N, 0.5)`로 수행한다. **tie 전량을 대립가설에
불리한 쪽에 세우는** 것이다.

```
조건부 추정치   0.927410
보수적 추정치   0.879850     ← tie 196,718건을 전부 반대편에 세운 값
```

그럼에도 방향이 유지된다. 이것이 뜻하는 바는 명확하다 — **zero-exclusion이라는 관례가 결론을
만들어낸 것이 아니다.**

## 8. bootstrap CI가 왜 퇴화했는가

95% percentile bootstrap CI의 두 끝점이 같다.

```
[0.28768207245178085, 0.28768207245178085]
```

이것을 "불확실성이 0"으로 읽으면 안 된다. 이유는 자료의 구조에 있다.

1. `T_KO`, `T_EN`은 정수 count다.
2. 따라서 `TP`는 정수비이고 `logTP`도 조밀한 연속 outcome이 아니다.
3. `N = 3,835,988`인데 서로 다른 `logTP` 값은 **3,725개**뿐이다.
4. `ln(4/3)` 한 점에 **123,040개(3.2075%)** 가 정확히 몰려 있다.
5. 표본 중앙값의 순위가 이 거대한 point mass **내부**에 있다.
6. 재표집을 해도 중앙 순위가 이 덩어리를 벗어나기 어렵다.
7. 결과적으로 모든 replicate의 중앙값이 같은 격자점에 고정된다.

여유가 얼마나 되는지 보면 명확하다. point mass는 순위 1,841,885–1,964,924를 차지하고, 중앙
순위는 그 안쪽 깊숙이 있어 양쪽으로 약 76,000행의 여유가 있다. 이 정도를 벗어나려면 관련 계수가
표준오차의 약 39배만큼 움직여야 한다.

## 9. discrete lattice outcome의 통계적 의미

이 현상은 bootstrap의 결함이 아니다. 설계가 전혀 다른 두 절차가 같은 답을 준다.

**exact order-statistic interval** — 정렬된 표본의 두 순서통계량을 그대로 끝점으로 취하는
방법이다. 순위 1,916,074–1,919,915가 나오는데 둘 다 point mass 내부이므로 **이 구간도 퇴화**한다.

**source-stratified bootstrap** — 층 구성을 고정하고 층 내부에서 재표집하는 다른 설계다. 역시
같은 점에서 퇴화한다.

따라서 결론은 이렇다. **격자 위에 놓인 자료에서는 자료에 충실한 어떤 방법도 같은 답을 준다.**
더 넓은 구간을 주는 방법이 있다면 그것은 표본 중앙값이 아닌 다른 무언가를 기술하고 있는 것이다.
보고할 때 방법을 바꾸는 것이 아니라 **설명을 함께 붙이는 것**이 옳은 대응이다.

## 10. source-stratified sensitivity가 무엇을 해결하고 무엇을 해결하지 못하는가

SSOT §17.2는 source 불균형이 클 때 source-stratified bootstrap을 기본으로 쓰라고 규정한다. 이
cohort는 025가 64.8%, 026이 35.2%로 약 1.84:1이고, 더 중요하게는 두 층의 결과 분포가 실제로
다르다.

```
025-family    median logTP = 0.2744368    P(TP>1) = 83.36%
026-family    median logTP = 0.3087355    P(TP>1) = 96.50%
```

**해결하는 것** — 층 비율이 재표집에서 흔들려 결론이 뒤집히는 상황을 배제한다. 층 구성을
고정해도 결론은 그대로였다.

**해결하지 못하는 것** — 층 간 차이가 *왜* 생겼는지는 전혀 말해주지 않는다. 이 cohort에서
source와 domain은 분리 식별되지 않으며(SSOT §20.2), 그 판정은 G5의 identifiability 작업과 NB09의
설명모형에 속한다. 따라서 "026이 더 큰 source effect를 가진다"거나 "기술과학 domain이 TP를
키운다"는 진술은 **이 결과로부터 나올 수 없다.**

또 하나 눈여겨볼 점은 pooled median `ln(4/3)`이 두 층 어느 쪽의 median과도 일치하지 않는다는
것이다. "한국어의 token premium이 얼마인가"라는 질문에 단일한 답이 없을 수 있음을 시사하지만,
그 이상을 말하려면 identifiability가 먼저 해결되어야 한다.

## 11. known-direction sensitivity의 의미

cohort에는 번역 방향이 `UNKNOWN`인 행이 50,547건 있다. 이들을 제외한 부분집합에서도 동일하게
계산했다.

```
primary          N = 3,835,988   median = 0.2876821   P(Y>0) = 0.879850
known-direction  N = 3,785,441   median = 0.2876821   P(Y>0) = 0.879829
```

median이 보고 자릿수 전부에서 같다. 결론이 방향 메타데이터가 불확실한 행 때문에 만들어진 것이
아님을 보인다. 이 sensitivity는 primary cohort를 **대체하지 않고** 나란히 보고된다 — 방향
미상이라는 이유로 행을 버리는 것은 그 자체가 선택 편향이 될 수 있기 때문이다.

## 12. 결과가 강하다는 것은 정확히 무엇을 의미하는가

가장 흔한 오해는 "p가 극도로 작으니 강한 결과"라고 읽는 것이다. `N ≈ 3.8M`에서 p의 크기는 거의
정보를 담지 않는다. 이 결과가 강한 이유는 다른 데 있다.

| 층위 | 관측 |
|---|---|
| 효과 크기 | median TP = 1.333 — 실무적으로 즉시 체감되는 크기 |
| 유병률 | P(TP>1) = 87.99% — 분포 전반의 성질 |
| tie 처리 | tie 전량을 반대편에 세워도 방향 유지 |
| 방향 메타데이터 | UNKNOWN 제외해도 동일 |
| 층 구성 | source 고정 재표집에서도 결론 동일 |

**서로 독립적인 다섯 층위의 증거가 같은 방향을 가리킨다는 사실**이 강도의 근거다. 어느 하나가
결론을 떠받치고 있는 구조가 아니다.

## 13. RQ1이 아직 설명하지 못한 것

RQ1은 **존재와 크기**를 확립했을 뿐 **원인**에 대해 아무것도 말하지 않는다.

- 왜 한국어가 더 많은 token을 쓰는가 — 분해도 설명모형도 아직 없다.
- 형태소 구조 때문인가 — RQ4의 질문이며 NB09 이전에는 답할 수 없다.
- UTF-8 byte 표현 때문인가 — RQ2의 exact decomposition이 다룰 문제다.
- tokenizer의 regex chunking 때문인가 — RQ5이며 NB06/D-05가 아직 존재하지 않는다.
- domain이나 source 때문인가 — identifiability가 미해결이다.
- 다른 tokenizer에서도 같은가 — 측정 자체가 `o200k_base` 하나에 고정되어 있다.

이 목록은 한계의 나열이 아니라 **연구의 나머지 절반**이다.

## 14. RQ2–RQ5로 어떻게 이어지는가

RQ1이 확립한 것은 설명해야 할 대상이 실재한다는 사실이다. 이후 질문들은 그 대상을 분해한다.

**RQ2 — exact decomposition.** `logTP`를 `logCodePointRatio + logByteDensityRatio +
logCompressionPenalty`로 정확히 분해한다. 이 항등식은 전수 3,835,988 pair에서 최대 오차
8.88e-16으로 이미 검증되어 있다(G2). 남은 것은 각 항이 얼마씩 기여하는지의 해석이며 NB07 소관이다.

**RQ3 — representation association.** 길이·byte·공백·문자군 같은 표면형 feature가 `logTP`와
어떻게 연관되는지를 본다. NB09 설명모형.

**RQ4 — morphology incremental value.** 형태소 밀도·조사·어미·파생접사 비율이 RQ3의 통제 이후에도
추가 설명력을 갖는지 검정한다(M2 vs M1). D-03은 이미 측정되어 G4를 통과했으나, **RQ1 추론의
입력은 아니다.**

**RQ5 — regex chunk mechanism.** tokenizer의 regex pre-tokenizer가 어디서 경계를 만드는지를 본다.
NB06/D-05가 선행 조건이며 아직 시작되지 않았다. 현재 canonical 다음 단계가 바로 이것이다.
